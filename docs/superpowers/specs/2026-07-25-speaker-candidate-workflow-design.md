# 候选说话人确认与全量回填设计

日期：2026-07-25

## 目标

把字幕处理明确拆成“Whisper 转写”和“说话人识别”两步。算法先在不知道人数的情况下提出匿名候选人物；用户试听代表片段，将候选人物映射、合并或重命名为真实说话人；系统再用确认样本分类全部字幕。

## 数据边界

- `speaker-candidates.json`：无人工先验的匿名候选、逐条候选预测和代表试听片段。
- `speaker-candidate-assignments.json`：候选人物到真实说话人的人工映射。
- `speaker-predictions.json`：注册声纹分类后的算法预测、置信度和注册样本 ID。
- `manual-speaker-labels.json`：逐条人工标准答案。它不被算法预测覆盖。
- `manual-speakers.json`：稳定的真实说话人 ID 与可编辑显示名称。

多个匿名候选可以映射到同一个真实说话人，从而处理“算法提出 5 个候选、实际只有 4 人”的过聚类情况。名称只负责显示；人物关系由稳定 ID 和显式映射决定。

## 处理流程

1. Whisper 生成精确字幕和时间轴。
2. 声纹模型生成每条可用语音的归一化 embedding。
3. 使用冻结的外部阈值 AHC 自动得到候选簇，不传入人数或人工标签。
4. 每个候选选出最多 3 条靠近簇中心且时长足够的代表片段，网页通过原视频时间范围试听。
5. 用户将候选映射到已有说话人，或创建并可选重命名新说话人。
   - 候选包含多人、噪声或明显聚类错误时，用户可以标记为“混合声音 / 错误候选”。该状态视为已处理，但不创建人物、不进入注册声纹。
6. 全部候选确认后，以代表片段建立注册中心，分类全部有 embedding 的字幕；缺少 embedding 的短字幕只在左右结果一致时传播，否则保留“待确认”。
   - 被排除候选中的字幕不会删除，仍使用其他已确认人物的干净注册中心重新分类。
7. 字幕列表展示算法预测，同时保留逐条人工纠错入口。

## 评估

只有存在人工标准答案时显示评估。统计范围排除已软删除字幕，未人工标注字幕不进入准确率分母。

- 标注覆盖率：已标注条数 / 有效字幕总数。
- 标注内正确率：所有已标注字幕上的正确率，包含注册样本。
- 独立验证正确率：排除注册样本后的已标注字幕正确率。
- 每位说话人：support、correct、precision、recall、F1。
- 同时保留混淆项以及长短字幕分项；长字幕定义为时长不短于 1 秒。

## 兼容与错误处理

- 新视频在转写阶段自动生成候选数据；旧视频没有候选数据时提示重新生成字幕，不破坏既有人工标注。
- 候选未全部确认时禁止运行全量分类，并返回缺失候选列表。
- 映射到人物或明确排除都算候选已处理；只有尚未选择的候选阻止全量分类。
- 低置信度或无 embedding 字幕不强制归人。
- 当前生产链路先使用已安装的 ECAPA；候选工作流的接口保留模型名和阈值，使 CAM++ 可在不改网页协议的情况下替换。

## 验收

- 用户能够试听每个候选的代表片段，并将多个候选合并到同一人物。
- 未输入姓名时自动使用“说话人 N”，输入姓名后全局更新显示名。
- 全量分类后字幕列表立刻按预测人物更新。
- 人工标签和算法预测分别持久化，刷新后均能恢复。
- 部分人工标注也能显示正确率；独立验证指标排除注册片段。
