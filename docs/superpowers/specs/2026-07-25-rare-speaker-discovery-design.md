# 少数说话人发现实验设计

日期：2026-07-25

## 目标

在不读取当前视频人工说话人标签的前提下，验证以下假设：

1. 局部过聚类能避免少数说话人过早被大簇吞并。
2. 动态说话人注册能发现后半程才出现的新说话人。
3. 对局部微型簇等权处理，比按字幕数量累加全局中心更能保留少数说话人。
4. 结合 5、10、20 分钟多个尺度的稳定性，可以比全局 silhouette score 更准确地估计说话人数。

当前视频仅作为冻结测试集。人工标签只能被独立评分程序读取，不允许进入推理、阈值选择、人数估计或模型选择流程。

## 已比较的实现路线

### 路线 A：动态微型簇注册（首选）

每个时间窗口先生成多于预期人数的微型簇，再把可靠微型簇注册到全局说话人原型。局部簇和所有已有原型都不够相似时，创建候选新说话人；候选在多个片段或窗口重复出现后转为正式说话人。

优点：直接针对后出现的少数说话人；可以自然输出人数；可解释性强。缺点：需要在独立开发数据上校准“合并、新建、晋级”阈值。

### 路线 B：全局微型簇相似度图

先生成全部窗口的微型簇，然后把微型簇作为图节点，以声纹相似度作为边，最后做社区发现或谱聚类。

优点：没有窗口先后顺序偏差。缺点：长视频节点数量大；社区数量估计仍可能受阈值影响；不适合第一版快速定位问题。

### 路线 C：多尺度标签投票

分别运行 5、10、20 分钟聚类，对各尺度匿名标签做对齐和投票。

优点：实现简单。缺点：如果每个尺度都已吞掉同一个少数说话人，投票无法恢复；此前 ECAPA 与 CAM++ 标签投票实验已经显示此风险。

第一版选择路线 A，并用路线 B 的离线全局合并作为最终去重步骤。路线 C 只用于稳定性测量，不直接决定字幕标签。

## 推理数据流

```text
现有 ECAPA / CAM++ / ERes2NetV2 embeddings
                     ↓
         5、10、20 分钟窗口切分
                     ↓
        每个窗口过聚类为 6～10 个微型簇
                     ↓
       过滤低可靠、过短、单样本微型簇
                     ↓
    与全局说话人原型做一对一相似度匹配
          ↙                     ↘
    相似度足够高              相似度不足
    更新已有原型              创建候选原型
                                  ↓
                      跨窗口重复后正式注册
                     ↓
        对全局原型做一次离线相似度图合并
                     ↓
            稳定原型数量 = 自动人数
                     ↓
        将微型簇标签传播回长字幕和短字幕
                     ↓
            独立评分模块读取人工标签
```

## 核心规则

### 局部过聚类

- 不在窗口内强制聚成4人。
- 初始微型簇数量由窗口有效片段数决定，并限制在 6～10 个。
- 短于1秒的字幕不参与建立微型簇中心。
- 每个微型簇计算中心、簇内紧密度、累计语音时长和样本数。

### 动态注册

- 全局原型以“微型簇中心”为更新单位，不以字幕数量为更新单位。
- 每个微型簇最多匹配一个全局原型，使用 Hungarian 一对一匹配。
- 相似度不足的微型簇进入候选池，而不是强制塞入已有原型。
- 候选在至少两个独立片段出现，或累计达到通用最小时长后，晋级为正式说话人。
- 阈值必须来自公开基准、独立开发视频或模型校准数据，不能根据当前测试视频准确率选择。

### 多尺度人数估计

- 分别在 5、10、20 分钟尺度运行动态注册。
- 比较正式原型在不同尺度下的声纹中心相似度。
- 只有跨至少两个尺度稳定出现的原型才计入最终人数。
- 同时输出人数置信区间，例如 `3～4 人，4 人置信度 0.72`，不强制输出一个伪精确数字。

### 短字幕处理

- 短字幕不独立决定新说话人。
- 左右相邻长字幕标签一致时直接传播。
- 相邻标签不一致时，使用字幕自身 embedding 与两侧原型比较；低置信度则输出 `UNKNOWN`。
- 第一版允许 `UNKNOWN`，防止为了覆盖率把少数说话人错误吞入大簇。

## 防止测试集泄漏

推理程序必须满足：

- 不导入 `scoring.py`。
- 不接受人工标签文件参数。
- 输出文件生成后才允许执行评分命令。
- 配置文件不得保存根据本视频评分结果挑选出的阈值。
- 所有尺度和模型都用预先声明的参数批量运行，不根据中途分数停止或修改。

评分程序负责匿名标签的最优置换映射，这个映射只用于统计，不回写推理结果。

## 输出

每次实验生成：

```text
outputs/<run-id>/
├── config.json
├── inferred-speakers.json
├── prototypes.json
├── candidate-speakers.json
├── speaker-count.json
├── metrics.json
└── errors.json
```

必须记录：

- 自动估计人数及置信度。
- 每个说话人原型的样本数、累计时长和跨尺度稳定性。
- 全量准确率、Macro-F1、每位说话人的 precision/recall/F1。
- 长短字幕分项、混淆矩阵和 `UNKNOWN` 比例。
- 运行时间、峰值内存和 CPU 压力。

## 测试策略

实现遵循测试先行：

1. 微型簇不能被多数类样本数直接加权吞并。
2. 与已有原型相似度不足时必须创建候选，而不是强制匹配。
3. 候选未达到跨片段证据时不能晋级。
4. 同一候选跨窗口重复出现后应晋级为新说话人。
5. 多尺度中稳定存在的稀有原型应计入人数。
6. 推理模块尝试读取人工标签时测试必须失败。
7. 匿名标签置换只发生在评分模块。

## 验收标准

第一阶段验证成功需同时满足：

1. 不提供人数先验时，输出4个稳定正式原型，或把4人列为最高置信度估计。
2. 说话人3、4不再被完全吞并，二者长字幕召回率明显高于当前基线。
3. Macro-F1 高于当前 ECAPA 20分钟窗口的77.61%。
4. 全量准确率不低于当前94.94%基线。
5. 所有指标均来自冻结测试集的一次性最终评分；没有通过该测试集调阈值。

98～99%仍作为最终产品目标，但不作为第一阶段实验的虚假通过条件。如果第一阶段无法达到，则根据错误类型决定是否引入独立开发集、PLDA校准或说话人注册音频。

## 失败和降级

- embedding 文件缺失或索引不一致时立即失败，不自动换数据集。
- 某窗口有效样本太少时跳过该尺度并记录原因。
- 候选证据不足时保留为 `UNKNOWN`，不强行并入大类。
- 自动人数在不同尺度不一致时输出分布与置信度，不隐藏不确定性。
- 所有实验结果写入新目录，不覆盖现有生产输出。
