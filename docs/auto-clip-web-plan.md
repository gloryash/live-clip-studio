# 自动切片网页执行计划

## 目标

在直播完成字幕和说话人标注后，用户只选择直播和预制模板，点击一次“开始转换”，系统自动完成选题、配置校验、剪辑、渲染、封面、字幕和质量检查，并返回切片、传播系数和模型评价。

## 假设与边界

- 说话人流程已经完成，任务目录存在有效的 `transcript/speaker-turns.json`、候选分配和说话人预测。
- 现有 `live_clip_studio.clips.pipeline.execute` 是唯一的剪辑编排入口，网页不复制剪辑规则。
- 模型凭证只由 CC Switch/环境变量提供，浏览器和项目文件不保存 API key。
- “一般”模板沿用单人近景／中景及横向双人布局；按素材分辨率选择 `editing/layouts/` 的布局参数。
- 传播系数是模型对内容传播潜力的 0-100 估计，不是播放量承诺。

## 阶段与标准产出

| 阶段 | 输入 | 标准产出 | 失败信号 |
| --- | --- | --- | --- |
| 1. 资格检查 | job、媒体、说话人文件 | 可选直播列表；每项有 `ready` 和原因 | 缺视频、字幕未完成、候选未确认或预测缺失 |
| 2. 创建转换任务 | `job_id`、`template_id` | 持久化 `run.json`，状态 `queued` | 直播不存在、模板不存在、已有相同运行 |
| 3. AI 选题 | AI 精准字幕、模板参数 | `decisions.json`，每条含标题、hook、body、gold、virality | API 错误、Schema 校验失败、敏感词或时长不合法 |
| 4. 计划与渲染 | 决策、布局、源视频 | 每条 `.mp4`、`.srt`、`-cover.jpg` 和渲染报告 | 布局尺寸不匹配、FFmpeg 失败 |
| 5. 质量检查 | 成片、计划、字幕 | `qa/summary.json`，技术/解码/音频/语音检查结果 | 任何硬性检查失败则标记 `needs_review` |
| 6. 网页结果 | run 目录 | 切片数量、阶段、视频/封面/字幕链接、评分、评价、风险 | 结果文件缺失或无法读取 |

## 验收门禁

1. 未完成说话人标注的直播不会出现在可选列表，也不能通过接口启动。
2. 同一个直播和模板在运行中不能重复创建任务。
3. 页面刷新后通过 `GET /api/clip-runs/{run_id}` 恢复状态。
4. 完成结果中每条切片必须同时有视频、封面、字幕、`virality.score` 和 `virality.reason`。
5. 现有测试全部保持通过；至少用一场已标注的新直播完成一次真实渲染验收。

## 页面状态

网页显示：选择直播、选择模板、开始转换、当前阶段、已完成阶段、切片进度、错误信息和结果卡。模板采用卡片，不使用原生下拉框。
