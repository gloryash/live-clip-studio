# 自动发言者构图：执行与验收

## 约束与待验证假设

- 音频说话人编号不等于屏幕位置。姓名、身份、左右、画面大小、分辨率都不能证明人物正在发言。
- 人脸检测只能给出可见人物框。拟用音画同步的 active-speaker 模型判断每张脸与声音是否匹配；必须先在真实提问/回答片段验证，不能用嘴部像素变化代替。
- 输入是已经人工标注说话人的直播；沿用本地 macOS、FFmpeg 与 Python。源画面可能切换、存在小窗、头像水印、短插话、漏检或画外音。
- 输出窗口沿用参考片的包装；源裁切根据当前片段测量。小窗放大无法恢复源分辨率。
- 不确定时保留当前源画面并标 REVIEW，不能把最大脸或上一位发言者冒充当前发言者。该回退是产品保护策略，不声称参考片也如此处理。

## 顺序与标准产出

| 步骤 | 标准产出 | 验收条件 |
|---|---|---|
| 1 根因与参考核对 | 本文、错误源时间、旧裁切证据 | 区分音频标注、人脸检测、音画关联、镜头规划各环节；确认参考文件 |
| 2 模型最小实测 | 原片提问/回答的逐脸模型分数 | 不输入身份或位置，主持人与嘉宾轮流发言能区分；不行先重新分析 |
| 3 可复用分析 | 本片检测轨道、逐段分数、匹配/拒绝原因 | 处理小脸、漏检与镜头变化；结果可追溯且不会跨素材套位置 |
| 4 模板集成 | 说话人时间边界→已确认脸→裁切框 | 短插话也按边界切，删除基于最大脸和人工位置的自动捷径；不叠放双人 |
| 5 质检与缓存 | REVIEW 原因、版本指纹、自动测试 | 未知人物/画外音/歧义不伪装 PASS；旧片保留，新渲染不复用旧构图 |
| 6 真实渲染 | 问题切片新成片、源帧→裁切→成片对照 | 全片解码、音画时长、切人准确性、主体占比同时验证；再测另一种布局 |

## 问题样例

历史任务 `59d0bc4d-7bde-469d-8faa-535d163c5924` 的 `03-game-time`，102.27 秒。77 是传播评分，开头真实源时间为 5017.30 秒（83:37）。5017.30–5025.36 是主持人提问，接着嘉宾回答。旧渲染在提问时裁主画面嘉宾。

确认的缺陷：缩到宽 456 检测漏掉小窗；自动选最大脸；仅人工位置明确且持续 1.8 秒以上才切说话人；按分辨率借用其他素材场景框；说话人构图不确定未进入总质检。
